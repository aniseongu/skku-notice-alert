## 주의

- Gemini의 해당 없음과 확인 필요는 보수적으로 제외한다. 판정이 없으면 명확한 직무만 사용한다.
- 직무 정보가 이미지에만 있거나 범용 채용 공고에서 본문을 아직 받지 못하면 소프트웨어 직무가 있어도 누락될 수 있다.
- 실제 알림 여부는 새 글 여부, 기존 pending, 알림 연결 및 실행 당시 기준에 따라 다르다.

## 최종 정책

- 학교 게시판 새 공지는 전부 알린다. 첫 기준선과 중복 방지는 유지한다.
- 인턴의 IT 관련성과 지원 가능성은 Gemini가 공개 본문 전문과 최대 세 장의 공고 이미지를 읽고 판단한다. 소프트웨어학과 학부생이라는 기본 맥락을 주며 개인 프로필 원문은 이 전용 호출에 넣지 않는다.
- relevant만 알린다. maybe와 not_relevant는 목록에 남기며, 키가 없거나 본문, 이미지, API 응답이 준비되지 않으면 알림 판단을 pending으로 미룬다. 제목 키워드 규칙으로 대체하지 않는다.
- 신규 및 대기 글을 먼저, 남는 자리로 과거 글을 최대 6건씩 분석한다. 과거 글은 화면의 이유만 보완하고 새 알림을 만들지 않는다. 본문, 제목, 이미지 주소와 모델의 지문으로 재호출을 줄인다.
- 학교와 인턴의 이미지 요청은 합계 10장, 글당 3장, 장당 5MB, 요청 사이 1초다. 확인된 공개 이미지 호스트만 HTTPS로 읽으며 리디렉션과 사설 IP는 거부한다. 이미지를 읽지 못한 공고는 제목만 보고 통과시키지 않는다.
