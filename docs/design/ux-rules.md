# UI/UX 규칙

> 앱 이름은 성공, 학교 게시판 탭 이름은 성대 공지다. 화면이 어떻게 동작하고 무엇을 말하는지. 시각 토큰은 `docs/DESIGN.md`, 플랫폼별 차이는 `platforms.md`.

## 1. 화면이 답하는 질문

- 한 화면 한 질문(taste-skill app-screens): "지금 내가 챙겨야 할 공지는 무엇이고, 언제까지인가?"
- 탭: "성대 공지"(성균관대 게시판만, 최신순과 마감순 선택), "인턴 공고"(링커리어와 자소설닷컴, 최신순과 마감순 선택), "저장". 사용자 결정(2026-11-03): "전체"라고 하지 않고 "성대 공지".
- 행을 누르면 앱 안 상세를 먼저 보여 준다(D-013): 요약, 판정, 마감, 첨부, 본문. 원문(학교 홈페이지)은 "원문 열기"로 연다.
  휴대폰은 전체 화면 상세로 넘어가고 뒤로 가기로 목록에 돌아온다. 앞으로 가기는 그 상세를 복원한다(history). Windows는 오른쪽 상세 칸에 보인다.
  Ctrl이나 Cmd를 누른 채 누르면 바로 원문을 새 탭에 연다.
- 상세의 순서는 내용이 먼저다: 제목, 판정 한 줄, 마감 한 줄, 요약, 본문, 첨부, 그리고 맨 아래 작게 글 정보(게시일, 관심, 알림 여부). 알림을 보냈는지 같은 관리 정보를 내용 위에 두지 않는다(사용자 지시 2026-11-02).
- 본문은 준비 중, 재시도 예정과 가져오기 실패를 구분해 안내한다. 대기와 실패를 같은 상태로 보이게 하지 않는다.
- 검색과 필터 결과에서 제외된 글은 상세에 남기지 않는다. 선택 메뉴 밖으로 키보드 포커스가 나가면 메뉴를 닫는다.
- Windows 상세 칸은 닫을 수 있다(머리 줄 왼쪽 닫기, Esc). 닫으면 목록이 넓어지고, 목록 머리의 칸 아이콘이나 행 누르기로 다시 연다. 열고 닫은 상태는 기억한다.

- 공지 보기 조건: 읽지 않은 공지만과 정렬을 한 줄에 맞춘다. 필터는 체크 표시가 있는 단추, 정렬은 오른쪽 선택 메뉴다. 읽음 필터는 기본 끔, 기기에 기억하고 저장 목록에는 적용하지 않는다.
- 고정 공지도 원래 게시일 위치에 글 번호별 한 번만 표시한다. 별도 고정 목록으로 복제하거나 숨기기 단추를 두지 않는다.
- 읽지 않은 공지만 보는 중에는 현재 읽는 공지를 상세를 닫거나 다른 공지로 이동할 때까지 남긴다.

## 2. 목록 행

- 휴대폰: [메타 한 줄, 오른쪽 끝 D-day] > 제목 최대 2줄 > 판정 한 줄. 분류 아이콘 타일과 게시일은 넣지 않는다(DESIGN 6절).
- Windows 넓은 칸: [메타 열 120px] [제목과 판정] [D-day] 세 열.
- 메타: 게시판 짧은 이름과 분류를 한 가지 모양(13px, 500, `--text-3`)으로. 고정 글은 "고정". 점이나 가운뎃점으로 잇지 않는다.
- 판정 줄 앞말: 관심 키워드에 맞으면 "관심 <키워드>"(진녹), 아니면 AI 판정어. 판정어와 이유 문장 끝이 같은 말을 되풀이하지 않게 Gemini 프롬프트에서 막는다.
- 제목 앞뒤의 이모지는 표시할 때 지운다(원문 링크는 그대로).
- AI 판정: "해당"(진녹), "확인 필요"(주황), "해당 없음"(회색)을 이유 앞에 굵게. "해당 없음" 행은 전체를 흐리게(직방의 "계약완료" 처리).
- 날짜 묶음: 성대 공지의 최신순과 저장은 게시일로 "오늘", "어제", "11월 1일 (토)". 두 목록의 마감순은 "오늘 마감", "3일 안", "일주일 안", "일주일 뒤"로 묶고, "마감일 미정"과 "마감 지난 글"은 뒤에 둔다. 정렬만으로 글을 숨기지 않는다.
- 마감 표기(아캠 플러스 `remainingText` 규칙을 공지 일 단위로 줄임): 지남 "마감", 오늘 "오늘", 그 밖 "D-n". 3일 이내는 `--danger`.

- 메타 줄 낱말(같은 모양, 쉼표로 잇기): 분류, "고정", "수정됨"(학교가 고친 글, D-025), "저장함". 알약, 배지, 아이콘으로 만들지 않는다.
- 마감 줄: 제목 정규식이나 본문(Gemini, D-023)에서 찾은 날짜. 종류가 "일정"이면 "일정 11월 18일"처럼 쓴다.
- 상세에서 고친 글은 마감 줄 아래 "11월 3일에 학교가 제목을 고쳤어요" 한 줄, 바뀌기 전 제목은 맨 아래 글 정보의 "이전 제목".

- 외부 인턴 공고(D-026, D-028): 성대 공지 탭에 넣지 않는다. 인턴 공고 탭과 저장에서 볼 수 있다. 상세에서는 수집한 본문과 이미지를 학교 공지와 같은 방식으로 보여 준다.

## 2-1. 관심 키워드

- 사용자 요청(2026-11-02): "겨울방학 인턴 이런 키워드를 입력하면 관련된 것도 중요로 표시, 왼쪽에 키워드 관련 공지들을 볼 수 있게".
- 입력: 휴대폰은 키워드 칩 줄 끝 "키워드 추가", Windows는 사이드바 "관심 키워드" 절의 "추가". 엔터로 저장, 길게 누르기나 오른쪽 x로 지우기.
- 맞추는 법(D-024): 키워드를 띄어쓰기로 나눈 낱말이 제목, 분류, 본문, 그림 속 글자에 **그대로 모두** 들어 있으면(띄어쓰기 무시) 맞는다.
  비슷한 말이나 뜻으로 맞추지 않는다. 판정 이유 문장은 보지 않는다(사용자 지시 2026-11-03 "인턴이라고 적혀있어야 인턴이지").
- 표시: 맞는 글은 판정 줄 앞에 "관심 겨울방학 인턴". 키워드 줄(칩, 사이드바)에 맞는 글 수.
- 저장: GitHub 변수 `INTEREST_KEYWORDS`로 모든 기기와 맞춘다(D-018).

## 2-2. 설정 화면

- 들어가기: 휴대폰은 상단 바 톱니, Windows는 사이드바 아래 "설정". 주소는 `?view=settings`.
- 배치: 한 열, 줄마다 왼쪽에 이름과 한 줄 도움말, 오른쪽에 입력이나 단추. 줄 사이 1px 구분선.
  휴대폰은 목록과 같은 흰 묶음 상자(One UI 설정, DESIGN 6절), PC는 상자 없이 칸 전체 폭. 상자 안에 상자를 또 넣지 않는다.
- 나가기: 머리 왼쪽 "설정 닫기"(모든 폭)와 Esc. 들어오기 전 보기로 돌아간다.
- 절 순서: 연결 > 알림 받을 곳 > 연결 키 > 관심 키워드 > 캘린더와 피드 > 화면.
- 연결: GitHub 토큰(이 저장소의 Secrets, Variables만)은 한 번 넣으면 이 기기에 암호화해 기억한다(D-017). 처음 여는 기기는 한 번 넣는다.
- 알림 받을 곳: "이 기기 알림"(기기마다 켜고 끔, 8대까지, D-019)과 "알림 받을 분류"(끈 분류는 모두 알림에서만 빠짐, D-018). ntfy 칸은 없다.
- 연결 키: Gemini 키, 아이캠퍼스 토큰, 내 프로필. 키 값은 GitHub Secrets로 바로 암호화해 보내고 브라우저에는 저장하지 않는다.
  저장된 키는 다시 보여 주지 않고 "입력돼 있어요"와 "수정하기"만 보인다(GitHub처럼 쓰기 전용).
  키마다 "받는 방법" 펼치기(단계와 바로가기 링크)와 "확인"(Gemini는 실제로 모델 목록을 불러 키가 맞는지 본다).
- 관심 키워드, 저장, 읽음은 GitHub 변수로 모든 기기와 맞춘다(D-017, D-018).
- 화면 모드: 자동, 밝게, 어둡게. 고르면 바로 바뀌고 저장 단추가 없다(웨일 아캠 플러스와 같음). 도움말은 "자동은 휴대폰과 PC 설정을 따라요" 한 줄.
- 입력칸은 `type=password`와 "보기" 단추, `autocomplete="off"`, 붙여넣기 허용. 오류는 칸 바로 아래 한 줄.

## 3. 상태

| 상태 | 보여 줄 것 |
|---|---|
| 처음 불러오는 중 | 실제 행과 같은 모양의 정적 스켈레톤 5줄. 상단 바 아래 글자 "불러오는 중" |
| 빈 목록 | 은행잎 아이콘 + 한 줄 제목 + 다음 행동 한 줄. 예: "지금 챙길 공지가 없어요" / "기준에 맞는 새 글이 오면 알림과 함께 여기 쌓여요" |
| 검색 결과 없음 | "'장학'에 맞는 공지가 없어요" + "검색어 지우기" 단추 |
| 불러오기 실패, 이전 목록 있음 | 목록은 그대로 두고 토스트 "목록을 새로 받지 못했어요. 잠시 뒤 다시 시도해 주세요" |
| 불러오기 실패, 목록 없음 | 빈 상태 자리에 같은 문구 + "다시 시도" 단추 |
| 갱신이 늦음 | `generated_at`이 2시간 넘게 지나면 상단 바 아래에 "11월 2일 19:00 기준, 확인이 늦어지고 있어요"(빨강 글자) |
| 판정 파일 없음 | `matched.json` 없이도 성대 공지, 인턴 공고와 저장을 표시한다 |

- 게시판 한 곳만 실패한 경우(아캠 플러스 "N건을 불러오지 못했어요" 방식)는 API에 게시판별 성공 시각이 생기면 붙인다. 지금 JSON에는 없다.

## 4. 문구 (스킬 `toss-ux-writing`)

- 정본은 스킬 `toss-ux-writing`(웨일 확장에서 가져옴)이다. 해요체, 능동형, 긍정형, 단추는 동사, 오류는 할 일, 사과하지 않기, 사용자 말.
- 문구를 새로 쓰거나 고치면 그 스킬의 점검표를 돌리고 아래 용어집에 맞춘다. 2026-11-02 첫 전수 검토(사용자 질문 "ui ux로 적혀있는 문자들도 다 검토를 한거야?").

### 단추

동사로 쓴다: 원문 열기, 링크 복사하기, 새로고침, 연결하기, 키 확인하기, GitHub에 저장하기, 테스트 알림 보내기, 새로 만들기, 추가하기, 삭제,
다시 불러오기, 검색어 삭제, 설치하기, 앱으로 설치하기, .env 양식 복사하기, 휴대폰 알림에도 쓰기, 보기, 숨기기, 닫기. "취소", "지우기", "확인"(단독)은 쓰지 않는다.

### 알림 문구 (ntfy)

- 공지: 제목 "[게시판] 공지 제목", 본문 첫 줄 "관심 <키워드>"(있으면), 다음 줄 AI 이유, "마감 11월 16일(월) 13:00", "<기준> 기준에 맞아요".
- Canvas: 제목 "과제 마감까지 3시간 남았어요", 본문 항목 이름, 다음 줄 "과목, 11월 12일(목) 23:59 마감". 연결이 끊기면 "아이캠퍼스 연결이 끊겼어요" / "설정 화면에서 아이캠퍼스 토큰을 새로 넣어 주세요".
- 여러 건이 한 번에 맞으면 묶음 알림을 검토한다(아캠 플러스, M4).

## 5. 입력과 접근성

- 터치 영역 44px 이상(행 전체, 탭, 칩). 아이콘만 있는 단추에는 `aria-label`.
- 포커스는 `:focus-visible`에 2px `--accent` 외곽선. `outline: none`만 쓰지 않는다.
- 키보드(데스크톱): `/` 검색, `j`/`k` 또는 위아래 화살표로 행 이동, `Enter` 원문 열기, `Esc` 상세 칸 닫기, `1` `2` `3` 탭 전환, `r` 새로고침, `?` 단축키 창.
- 단축키 표시(GitHub Primer `KeybindingHint` 참고): 키 하나에 `<kbd>` 하나, 사방 같은 1px 테두리, 11px 흐린 글자, 최소 폭 20px.
  쓰는 자리: 검색칸 오른쪽 `/`, 주 단추 안 `Enter`(단추 색에 맞춘 테두리), 사이드바 "단축키 ?" 줄, `?` 단축키 창(목록, 이동, 그 밖).
  나머지 단추는 `title`("새로고침 (R)")과 `aria-keyshortcuts`로만 알린다. 키 이름은 글자로 쓴다(Enter, Esc). ⏎, ↑ 같은 기호는 쓰지 않는다(웨일 DESIGN 1절).
  마우스와 키보드가 있는 기기(`hover: hover`, `pointer: fine`)에서만 보이고 휴대폰에서는 숨긴다. 문장형 안내("j, k로 옮기고...")는 쓰지 않는다.
- 학교 게시판에서 온 글자는 Lit 템플릿으로만 넣는다(`innerHTML` 금지, 자동 이스케이프).
- 고른 탭과 게시판은 `localStorage`에 기억하되, 읽기와 쓰기는 `try`로 감싸고 실패해도 화면은 돈다.
