# 세션 인수인계

전제: 다음 도구는 **이 저장소 외에는 아무것도 모른다.** 대화 내용은 넘어가지 않는다.

## 넘겨줄 때 (남은 토큰이 적다고 느끼면 즉시)

1. **동작하는 상태**까지만 커밋한다. 깨진 중간 상태는 커밋하지 말고 HANDOFF에 "미커밋 변경 있음: 파일 목록"으로 적는다.
2. `HANDOFF.md`를 **덮어쓴다**(40줄 이내). 맨 위 "마지막 갱신" 줄에 날짜, 도구, 모델을 적는다. 절은 그대로 쓴다:
   - 상태: 마일스톤, 계획 파일(체크박스 N/M), 완료한 것과 검증 방법(커밋 hash), 진행 중인 지점(파일:줄), 결정 대기
   - 사용자가 할 일
   - 알아 둘 것 (실패한 시도와 이유 포함)
   - 다음 3단계
3. 계획 파일의 체크박스를 실제 진행에 맞춘다. 마일스톤이 끝났으면 `GOAL.md`도.
4. daily-log에 오늘 한 일을 추가한다.
5. 커밋한다: `docs(repo): handoff - <한 줄 상태>`.
6. (Claude에서 Codex로) 사용자에게 `/codex:transfer`를 안내해도 된다. 필수는 아니다.

## 이어받을 때

1. `HANDOFF.md`, `GOAL.md`, `git log --oneline -15`, `git status --short`를 본다.
2. HANDOFF와 git이 다르면 **git이 맞다.** 미커밋 변경이 있으면 `git diff --stat`으로 범위를 본다.
3. 계획 파일의 남은 체크박스를 읽고 "다음 3단계"의 1번부터 진행한다. 시작 전에 사용자에게 한 줄로 어디서 이어 가는지 알린다.

## 하지 말 것

- HANDOFF.md에 이력을 쌓지 않는다. 이력은 daily-log와 git의 몫이다.
