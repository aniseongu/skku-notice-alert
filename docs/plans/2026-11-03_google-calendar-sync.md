# 구글 캘린더 자동 연결

- 상태: 진행 중
- 마일스톤: M4
- 작성: 2026-11-03, Claude
- 시작 hash: a2d47ec
- 완료 조건: 설정에서 한 번 연결하면 Actions 실행마다 "성대 공지" 캘린더에 내 공지와 저장한 공지의 마감이 들어가고, 저장을 지우거나 마감이 지나면 빠진다. 기기가 모두 꺼져 있어도 된다.

## 배경

사용자 요청: "구글 캘린더에 연결하는거 자동으로 되게 해줄 수 있어? 우리 아캠 플러스에서 하던거처럼". 아캠 플러스(WhaleExtentions D-026, D-027)는 사용자 OAuth 클라이언트, `calendar.app.created` 범위, 보조 캘린더, 마감 30분 전부터 마감까지 일정, 코드 흐름 갱신 토큰을 썼다. 우리는 브라우저 대신 Actions가 맞춘다.

## 가져올 코드

WhaleExtentions `extensions/icampus-check/gcal.js`의 범위, 일정 모양, 우리 일정 표시(extendedProperties.private), 코드 흐름과 PKCE.

## 단계

- [x] 브라우저: OAuth 코드 흐름(PKCE, offline, prompt=consent)을 팝업과 `oauth-callback.html`로 받고, 토큰 교환 뒤 캘린더를 만들어 클라이언트 ID, 비밀번호, 갱신 토큰은 GitHub Secrets에만, 캘린더 id는 변수(GOOGLE_CALENDAR_ID, 다시 연결할 때 같은 캘린더를 쓰려고)에 저장한다. 브라우저에는 남기지 않는다.
- [x] 서버: `gcal.py`가 갱신 토큰으로 접근 토큰을 받고, 우리 일정 목록과 원하는 일정을 비교해 넣기, 고치기, 지우기. 실패는 상태 코드만 남기고 공지 실행을 막지 않는다.
- [x] 워크플로: 수집 뒤 별도 단계, `continue-on-error`.
- [x] 설정 화면: 클라이언트 만드는 방법(아캠 플러스 프로젝트 재사용 가능), 연결, 연결 끊기.
- [ ] 테스트(httpx 대역), 정식 주소 확인, 기록, 커밋.

## 위험과 되돌리기

- 구글 앱이 "테스트" 게시 상태면 갱신 토큰이 7일 뒤 만료된다. 안내에 "프로덕션"으로 바꾸라고 쓴다(검증 전 경고 화면은 본인만 보므로 괜찮다).
- 범위는 `calendar.app.created`만. 사용자의 다른 캘린더는 읽거나 쓰지 않는다.
- 되돌리기: 설정의 연결 끊기(Secrets 삭제), 구글 계정 권한 화면에서 앱 권한 해제.
