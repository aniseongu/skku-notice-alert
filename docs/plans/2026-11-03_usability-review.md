# 본문 상태와 공지 서비스 사용성 검토

- 상태: 완료
- 마일스톤: M4
- 작성: 2026-11-03, Codex
- 시작 hash: bb81e19
- 완료 조건: 본문 미표시 원인을 실제 기록으로 구분하고 화면에 표시한다. 정식 화면을 외부 UX 기준으로 검토하고 다른 공지 및 수집 서비스의 기능과 출처를 정리한다.

## 배경

사용자는 본문이 보이는 글과 보이지 않는 글을 구분하기 어렵고 다른 서비스의 기능과 UX 기준 비교를 요청했다.

## 가져올 코드

기존 상세 출력과 렌더링을 유지하며 상태 필드만 추가한다. NN/g, W3C WCAG와 Primer 공식 기준을 참고한다. 기능 조사는 GitHub 원본 README와 공식 문서를 쓴다.

## 범위 밖

미리 정하지 않은 전체 화면 개편과 대규모 기능 추가는 이번 조사 결과에 따라 제안한다.

## 단계

- [x] 1. 최신 수집 기록의 완료, 대기와 실패를 확인한다.
- [x] 2. 본문 상태와 연속 탐색 오류를 고쳐 검증, 배포했다.
- [x] 3. 실제 화면의 사용성과 외부 서비스 기능을 비교해 문서로 정리한다.
- [x] 4. 탭, 필터, 검색, 상세, 뒤로 가기, 저장, 설정과 키보드의 연속 동작을 검증한다.
- [x] 5. 기록과 인수인계를 갱신하고 커밋한다.

## 추가 범위

- 사용자 요청: 내 공지 탭을 제거한다. 학교, 인턴, 저장의 세 탭으로 정리하고 기존 주소는 학교 공지로 연결한다.
- 사용자 요청: 비교한 오픈소스에서 도움이 되는 기능을 반영한다. 읽지 않은 공지만 보기와 고정 공지 숨기기를 추가하고 검증한다.
- 상세를 새로 연 뒤 설정에서 돌아오면 예전 글이 다시 열리는 문서 간 history 상태 불일치도 재현해 고친다.

## 추가 이름과 PWA 범위

- 사용자가 선택한 성공을 앱 이름으로 반영하고 학교 탭과 구분한다.
- 웹 검색을 바탕으로 마감 임박을 마감순 보기로 바꾸고 두 탭의 정렬을 통일한다.
- PWA 설치 정보, 상태 표시줄 색, 이미지 크기와 서비스 워커 및 오프라인을 검증한다. 실제 OS 설치는 별도 확인이다.

## 마지막 보기 제어 변경

- 사용자 요청으로 고정 공지 숨기기를 제거한다. 같은 글은 한 번만 표시하고, 읽음 필터와 정렬을 한 줄로 정돈한다.

## 위험과 되돌리기

API v1에는 추가 필드만 넣는다. 기존 데이터를 읽는 화면도 기본 상태 추론으로 동작한다. 수집 간격과 게시판별 요청 수는 바꾸지 않는다.
