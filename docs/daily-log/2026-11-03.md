## 1. [notify] 앱을 닫아도 받는 브라우저 알림과 저장된 키 잠금  (Codex 구현, Claude 이어받아 리뷰와 커밋)

- 요청: 웨일 확장처럼 앱이나 탭을 닫아도 알림이 뜨게 해 달라. 설정에 넣은 키가 저장 안 된 것처럼 보이고 새로고침하면 사라진다.
- 변경: `webpush_notify.py`로 VAPID 웹 푸시 직접 발송(ntfy는 선택). `notify._deliver`가 설정된 모든 채널을 시도하고 하나라도 실패하면 pending(최대 3회, D-005). PWA 워커에 `push-handler.js`(학교 주소만 열기). 설정 화면에 "이 기기 알림", 저장한 키는 날짜만 기억해 잠그고 "수정하기"로 다시 연다. 저장 전 새로고침은 경고. 수동 `test-push.yml` 추가.
- 검증: `scripts/check.sh` 통과(Canvas 날짜 의존 테스트 고정 포함), `npm test` 4개, 웹 빌드 통과. GitHub Secrets에 `WEB_PUSH_PRIVATE_KEY`, `WEB_PUSH_SUBSCRIPTION` 이름 존재 확인(값은 보지 않음).
- 미확인: 정식 Pages에는 아직 푸시 코드가 없다. 기존 구독은 로컬 미리보기에서 만든 것으로 보여 배포 후 정식 주소에서 "알림 받기"를 다시 눌러야 한다. 실제 웨일 수신과 클릭, 디자인 캡처 평가는 push 뒤에 한다. Codex 한도 소진으로 Claude가 리뷰했다.

## 2. [core] 새로고침해도 GitHub 연결과 저장한 키 표시 유지  (Claude)

- 요청: 키를 넣으면 계속 저장된 상태로 보여야 한다. 새로고침이나 재연결하면 다른 API 키도 깨진다.
- 원인: 토큰을 기억하지 않아 새로고침마다 연결이 끊겼고, 이전에 저장한 키는 연결 전까지 빈칸으로 보였다.
- 변경: 토큰 기억과 자동 재연결, "연결돼 있어요"와 "연결 끊기", 저장 뒤 ntfy 경고 문구 숨김. D-017.
- 검증: 로컬 빌드에서 Playwright(Chrome) + GitHub API 대역으로 연결, Canvas 저장, 새로고침 뒤 연결 유지와 키 4개 잠금 확인. 키 값이 localStorage에 없음을 확인. 웹 테스트 4개와 빌드 통과.
- 남은 것: push(배포)는 사용자 승인 대기. 배포 뒤 정식 주소에서 웨일과 Chrome으로 다시 확인.

## 3. [core] 관심 키워드를 모든 기기에서 같게  (Claude)

- 요청: "저장되게 해달라고. 모든 디바이스에서". 저장 날짜 표시는 필요 없다.
- 변경: 연결할 때 GitHub 변수 `INTEREST_KEYWORDS`를 읽어 키워드를 맞추고(GitHub 값이 기준), 바꿀 때마다 자동 저장. "휴대폰 알림에도 쓰기" 단추 제거. 저장한 키는 날짜 대신 "입력돼 있어요". 인터넷 오류에는 GitHub 값을 덮어쓰지 않는다.
- 검증: Playwright(Chrome) 두 기기 대역으로 A에서 추가, B 연결 시 같은 키워드, B 삭제 뒤 새로고침과 GitHub 값 반영 확인. 빌드와 웹 테스트 통과.

## 4. [core] 연결 토큰 암호화 보관과 화면 문구에서 웨일 대신 브라우저  (Claude)

- 요청: 예전 GitHub 유출 사례처럼 키가 털리지 않게, 한 번 넣으면 다시 넣지 않게. 화면에 "웨일" 대신 "브라우저".
- 변경: 토큰을 기기 전용 비공개 키(AES-GCM, 내보내기 불가)로 암호화해 IndexedDB에 보관. classic 토큰 거부. 화면과 테스트 알림 문구의 "웨일"을 "브라우저"로. D-017 갱신.
- 검증: 빌드와 웹 테스트 통과. 실제 정식 주소 확인은 배포(push) 승인 대기.
