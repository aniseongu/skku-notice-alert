# 공지 서비스 사용성 검토와 기능 비교

확인: 2026-11-03, Codex. 저장소 README와 공식 문서를 확인했으며 다른 서비스의 실제 운영 상태까지 검증한 것은 아니다. 우리 화면은 정식 주소에서 확인했다. 휴리스틱 검토이며 실제 사용자 실험이나 WCAG 적합성 인증은 아니다.

## 본문이 일부만 보이는 이유

최신 원격 archive를 확인한 시점에 학교 공지 59건은 모두 본문이 있었다. 인턴 공고는 링커리어 31건 중 15건, 자소설닷컴 30건 중 15건을 수집했다. 나머지 31건은 시도 전이며 실패 기록은 없었다. 새 글을 먼저, 사이트별 실행당 5건씩 읽는 정책 때문에 시간차가 생긴다.

미수집, 재시도, 실패를 같은 원문 안내로 보여 준 것이 사용성 문제였다. 상세 API에 body_status를 추가해 화면에서 상태를 나눠 안내한다. 기존 API 필드는 유지한다. 이미지 서버 장애나 개별 공고 제한은 이 집계만으로 전부 배제할 수 없다.

## 적용한 외부 기준

- [Nielsen의 10가지 휴리스틱](https://www.nngroup.com/articles/ten-usability-heuristics/): 상태를 알 수 있는지, 용어가 이해되는지, 선택 이유를 기억해야 하는지, 잘못된 행동에서 돌아올 수 있는지 검토한다.
- [WCAG 2.2 상태 메시지](https://www.w3.org/WAI/WCAG22/Understanding/status-messages.html): 대기와 실패 안내를 보조 기술도 인식할 수 있게 한다.
- [WCAG 2.2 클릭 영역](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html): AA 기준은 예외를 둔 24 CSS px 최소 크기다. 우리 자체 디자인 기준 44px과 혼동하지 않는다.
- [W3C 이미지 맞춤 기법](https://www.w3.org/WAI/WCAG21/Techniques/css/C37): 좁은 화면에서 가로 넘침을 피한다. 포스터 글씨의 가독성과 텍스트 대안은 별도로 살핀다.
- [GitHub Primer ActionMenu](https://primer.style/product/components/action-menu/): 메뉴 선택, 포커스와 키보드 조작을 검토한다. 시각 토큰은 우리 DESIGN.md를 유지한다.

## 우리 화면에서 확인한 것

| 우선순위 | 문제와 근거 | 조치 또는 제안 |
|---|---|---|
| 높음 | 미수집 글도 원문으로 가라는 안내만 있어 오류로 보임 | 준비 중, 재시도와 실패를 구분해 수정 |
| 높음 | PC에서 검색 결과가 없어도 전에 고른 공지가 상세에 남음 | 선택을 필터 결과 안에서만 찾도록 수정 |
| 중간 | 휴대폰에서 뒤로 간 다음 앞으로 가면 상세가 복원되지 않음 | 브라우저 history의 공지 상태를 복원하도록 수정 |
| 중간 | 게시판 메뉴가 Tab으로 빠져나와도 남고 Esc 후 정렬 단추로 포커스가 감 | 포커스 이탈 시 닫고 해당 게시판 단추로 정확히 복귀하도록 수정 |
| 중간 | 내 공지에 해당 없음인 글도 포함되어 이해하기 어려움 | 관심 키워드가 맞으면 포함되는 현재 규칙을 화면에서 설명할 필요. 오분류로 단정하지 않음 |
| 중간 | 마감순은 정렬과 함께 마감 없는 글과 지난 글도 숨김 | 마감이 남은 글만 보여 준다는 설명 권장 |
| 중간 | 이미지형 공고의 작은 글씨와 전체 내용의 텍스트 대안이 부족 | 확대 보기와 텍스트 대안을 차기 기능으로 권장. rich HTML의 원본 alt는 유지됨 |
| 중간 | 설정이 저장소와 토큰 입력부터 시작함 | 준비, 연결, 기기 알림 확인의 단계 안내 권장 |
| 낮음 | 수정됨 표시만으로 상세의 변경 정보를 발견하기 어려움 | 상세에서 변경 내용을 볼 수 있다는 단서 권장 |

좋은 점은 선택된 탭, 기준 시각, 건수와 마감 상태가 보이고 원문 열기 행동이 분명하다는 점이다. 320px, 412px, 1280px 목록에서 가로 넘침이 없었고, 보이는 button 중 24px 미만은 없었다. 모든 링크와 실제 터치 영역, 명도 대비, 스크린리더를 완전히 검증했다는 의미는 아니다. 캡처 기반 독립 평가는 7.5점이다.

## 권장 순서

1. 본문 상태와 탐색 오류를 먼저 고친다. 새 기능보다 현재 동작을 이해할 수 있어야 한다.
2. 내 공지의 포함 이유, 마감순의 범위, 캘린더 반영 범위를 화면에서 짧게 설명한다.
3. 읽지 않은 공지 필터와 본문 검색, 고정 공지 숨기기를 검토한다.
4. 저장한 공지에 메모와 지원 상태(검토 중, 지원 완료)를 붙이는 방안을 검토한다. 지원 상태는 위 서비스에서 확인한 동일 기능이 아니라 우리 사용 흐름에 대한 제안이다.
5. 이미지 확대와 텍스트 대안, 변경 전후 비교를 보강한다.

이 문서는 기능 조사와 제안이다. 제안 전체를 이번 작업에서 구현한 것은 아니다.
