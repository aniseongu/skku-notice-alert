# 문서/기록 규칙

| 문서 | 시점 | 성격 | 형식 |
|---|---|---|---|
| `GOAL.md` | 목표가 바뀔 때 (사용자 확인) | 마일스톤과 완료 조건 | 체크박스 |
| `docs/plans/YYYY-MM-DD_<topic>.md` | 작업 **전** | 계획, 체크박스로 진행 추적 | `docs/plans/TEMPLATE.md` |
| `HANDOFF.md` | 작업 **중**, 멈출 때 | 현재 상태만 (덮어씀) | 고정 절 |
| `docs/daily-log/YYYY-MM-DD.md` | 작업 **후** | 그날 한 일 (누적) | 아래 |
| `docs/DECISIONS.md` | 결정할 때 | 영구적인 "왜" (번호 누적) | D-NNN |
| `docs/research/*.md` | 조사할 때 | 사실 정보, 출처, 확인 날짜 | 자유 |

## 한국어 표기

- 가운뎃점, 화살표, 긴 줄표, 물결 같은 기호는 쓰지 않는다. 쉼표, "와/과", "부터/까지", "-"로 바꾼다(사용자 화면에서 글꼴이 깨짐).
  단, 게시판 원문을 그대로 인용할 때(예: 제목의 마감 표기)는 코드 표기 안에 그대로 둔다.
- 절 기호를 쓰지 않는다. "AGENTS.md 2절"처럼 말로 쓴다.
- `**굵게**` 바로 뒤에 조사를 붙이지 않는다.

## daily-log

- 날짜는 시스템이 알려준 오늘 날짜를 쓴다. 파일이 없으면 만들고, 있으면 **다시 읽은 뒤** 이어서 쓴다(다른 도구가 먼저 썼을 수 있다).
- 변경 하나마다 섹션 하나를 쓴다.
  ```markdown
  ## N. [<scope>] 제목  (Claude Code | Codex, 모델명)
  - 요청: 사용자 원문 일부
  - 변경: 파일과 함수 단위로
  - 검증: check.sh / --dry-run 실제 게시판 / 실제 알림 수신 / 확인 못 함 (솔직하게)
  - 커밋: <short-hash>
  ```

## plans

- 30분 넘게 걸리거나 되돌리기 어려운 작업(state 형식, 워크플로 권한, 알림 채널 변경)은 계획부터 쓴다.
- 단계는 `- [ ]` 체크박스로 쓰고 진행하면서 `- [x]`로 바꾼다. 다른 도구가 이어받을 때 이 체크박스를 기준으로 삼는다.
- 끝난 계획은 상단 `상태:`를 `완료`로 바꾸고 그대로 둔다(삭제하지 않는다). 마일스톤이 끝나면 GOAL.md 체크박스도 바꾼다.

## DECISIONS

- 형식: `## D-NNN 제목 (YYYY-MM-DD, 제안|확정)` 아래에 맥락, 결정, 대안, 주의를 짧게 쓴다.
- 뒤집힌 결정은 지우지 않고, 새 결정을 추가한 뒤 옛 결정에 "D-MMM으로 대체"라고 표시한다.
